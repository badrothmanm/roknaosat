# دليل النسخ الآمن (White‑Label): اسم الشركة، الشعار، التواصل، والدومين

الهدف: نسخ المشروع لعميل جديد **دون تسريب** اسم العلامة السابقة أو أرقامها أو دومينها.

---

## 1) نسخة نظيفة من الكود

- استخدم **مستودع Git جديد** أو نسخة مُفَرَّعة (branch) لعميل معيّن.
- **لا** ترفع ملف `.env` إلى Git (يجب أن يكون في `.gitignore`).
- انسخ `.env.example` إلى `.env` واملأ القيم الجديدة فقط.

---

## 2) الأسرار والبيئة (إلزامي)

| المتغير | الغرض |
|--------|--------|
| `SECRET_KEY` | مفتاح Django جديد عشوائي طويل (لا تعيد استخدام القديم). |
| `DEBUG` | في الإنتاج: `False`. |
| `DB_*` | قاعدة بيانات **جديدة** للعميل (أو نفس السيرفر باسم DB مختلف). |
| `CLOUDINARY_*` | حساب Cloudinary **خاص بالعميل** إن أردت عزل الوسائط تماماً. |
| `APPS_SCRIPT_URL` / `APPS_SCRIPT_KEY` / `GSHEETS_*` | سكربت Google وجدول CRM **للعميل**؛ لا تشارك مفاتيح جودة. |
| ملف `core/keys/crm-sheets.json` | إن استُخدم: استبدله بمفتاح خدمة Google **للمشروع الجديد** (لا تنسخ مفتاح جودة). |

---

## 3) معلومات الشركة (الاسم + أرقام التواصل)

في `.env` (انظر `.env.example`):

- `COMPANY_NAME` — الاسم القصير (يظهر في الواجهات والإدارة).
- `COMPANY_NAME_FULL` — الاسم الكامل.
- `COMPANY_PHONE` — رقم سعودي **بدون +** (مثال: `9665xxxxxxxx`).
- `COMPANY_WHATSAPP` — نفس الصيغة للواتساب.
- `COMPANY_INSTAGRAM` / `COMPANY_X_ACCOUNT` / `COMPANY_LINKEDIN` / `COMPANY_SNAPCHAT` — حسابات العميل.

**مهم:** في الكود ما زالت هناك **قيم افتراضية أو ثابتة** تشير إلى العلامة السابقة. بعد ضبط `.env`، نفّذ بحثاً في المشروع (انظر القسم 7) وتعدّل أي سطر لم يُقرأ من الإعدادات.

---

## 4) الدومين والاستضافة

في `core/settings.py` (حالياً القيم **مضمّنة** وليست كلها من `.env`):

- **`ALLOWED_HOSTS`**: أضف الدومين الجديد و`www.` إن لزم، واحذف أو علّق دومينات العميل السابق إن لم تعد تُستخدم.
- **`CSRF_TRUSTED_ORIGINS`**: نفس الدومينات بصيغة `https://...`.
- **`CORS_ALLOWED_ORIGINS`** (إن وُجد في الملف): حدّثها بنفس منطق الدومين العام.

بدون ذلك قد تظهر أخطاء CSRF أو 400 Bad Request بعد النشر.

---

## 5) الشعار والهوية البصرية

- **لوحة الإدارة (Jazzmin):** في `core/settings.py` → `JAZZMIN_SETTINGS` → `"site_logo": "img/logo.svg"`.
- ضع ملف الشعار الجديد تحت **`static/img/`** (نفس الاسم `logo.svg` أو غيّر المسار في `site_logo`).
- راجع أيضاً **الأيقونة / favicon** إن وُجدت في `templates/` أو `static/`.

---

## 6) حسابات المسؤول والمسوّق (اختياري لكن موصى به)

- `PRIMARY_ADMIN_USERNAME` — اسم مستخدم المدير المرجعي في القوائم.
- `PRIMARY_MARKETER_USERNAME` — المسوّق المرجعي «الأول».

بعد النسخ، أنشئ مستخدمي Django المناسبين أو عدّل الأسماء لتطابق العميل.

---

## 7) بحث إلزامي قبل الإطلاق (grep)

نفّذ في جذر المشروع (أو استخدم بحث المحرر) عن:

- `jodah`
- `966530460992`
- `jodah.sa` / `jodah.site` / `onrender.com`

**أماكن معروفة تحتاج مراجعة يدوية** (قد تتغير مع التحديثات):

| الملف | ماذا تفعل |
|-------|-----------|
| `listings/views.py` | `WHATSAPP_PHONE` ثابت — يفضّل ربطه بـ `settings.COMPANY_WHATSAPP`. |
| `static/js/main.js` | رقم واتساب افتراضي. |
| `static/js/behavioral_tracker.js` | رابط `wa.me` ومفتاح `localStorage` يحتوي اسم العلامة. |
| `templates/base.html` | روابط فيسبوك/إنستغرام/تويتر قديمة. |
| `listings/admin.py` | بناء رابط كامل بـ `https://jodah.site`. |
| `listings/services/sheets_sync.py` | `base_domain`. |
| `listings/x_utils.py` | رابط خاصية على `jodah.onrender.com`. |
| `app.py` | (إن استُخدم) مفاتيح وواتساب قديمة. |

أسماء CSS مثل `jodah-switch` أو معرفات DOM مثل `jodah-impersonation-bar` **لا تؤثر على العميل** لكن يمكن تغييرها لاحقاً للاتساق.

## 8) SEO وروابط عامة

- **`robots.txt` / `sitemap`** إن وُجدت: حدّث الدومين الأساسي.
- أي **بريد إلكتروني** أو **نصوص قانونية** في القوالب: راجعها يدوياً.

## 9) قائمة تحقق سريعة قبل Go‑Live

- [ ] `.env` جديد + `SECRET_KEY` جديد  
- [ ] `ALLOWED_HOSTS` + `CSRF_TRUSTED_ORIGINS` + CORS للدومين الجديد  
- [ ] `COMPANY_*` كاملة  
- [ ] شعار `static/img/` + `site_logo`  
- [ ] لا نتائج حساسة لـ `grep` على الاسم/الدومين/الرقم القديم  
- [ ] قاعدة بيانات ووسائط (Cloudinary) وCRM/Sheets للعميل  
- [ ] اختبار: تسجيل دخول إدارة، نموذج طلب، رابط واتساب

## 10) تحسين مستقبلي (للمطور)

لتقليل التعديل اليدوي: إضافة متغير واحد مثل `PUBLIC_SITE_URL` أو `SITE_BASE_URL` في `.env` واستخدامه في `admin.py` و`sheets_sync` و`x_utils` بدلاً من عناوين ثابتة.

---

## 11) سياسة الأدوار والصلاحيات (مدير عام / مدير مشارك / مسوّق)

هذا القسم مرجع تشغيلي سريع لتوزيع الصلاحيات في لوحة الإدارة.

### أ) مدير عام (General Admin)

- `is_staff = True`
- `is_superuser = True`
- وصول كامل لكل الأقسام، بما فيها:
  - `Users`
  - `Groups`
  - تغيير كلمات المرور والصلاحيات

**ملاحظات:**
- يفضّل أن يكون اسمه مطابقاً لـ `PRIMARY_ADMIN_USERNAME`.

### ب) مدير مشارك (Co-Admin)

- `is_staff = True`
- `is_superuser = False`
- عضو في مجموعة ضمن `CO_ADMIN_GROUP_NAMES` (الأفضل استخدام اسم `co_admin`).

**السلوك البرمجي الحالي:**
- يرى قائمة كبيرة مشابهة للمدير.
- ممنوع من `Users & Groups` (إخفاء في القائمة + `403` بالرابط المباشر).
- في النماذج التشغيلية الرئيسية (طلبات العقار / عروض التسويق / العملاء المحتملون):
  - **عرض + إسناد فقط**
  - لا إضافة
  - لا حذف
  - لا تعديل عام للحقول (عدا `assigned_to`)
  - تظهر فقط إجراءات الإسناد (`assign_to_marketer` و `assign_to_me`)

### ج) مسوّق (Marketer)

- `is_staff = True`
- `is_superuser = False`
- **ليس** ضمن مجموعة `co_admin`.

**السلوك:**
- قائمة مختصرة.
- وصول حسب الصلاحيات الممنوحة له ونطاق السجلات المسندة/المرتبطة به.

### د) إعداد متغير البيئة الخاص بالمدير المشارك

في `.env`:

```env
CO_ADMIN_GROUP_NAMES=co_admin
```

يمكن إضافة أكثر من اسم مفصول بفاصلة عند الحاجة.

### هـ) خطوات إنشاء مدير مشارك (Checklist)

1. أنشئ/حدّث مجموعة `co_admin`.
2. امنحها صلاحيات العرض المطلوبة على `listings` و`market`.
3. لا تمنحها صلاحيات `auth` (المستخدم/المجموعة/الصلاحية).
4. افتح المستخدم الهدف (مثل `h1`) واضبط:
   - `is_staff=True`
   - `is_superuser=False`
   - إضافة للمجموعة `co_admin`
5. تأكد من النتيجة:
   - تظهر قائمة الإدارة الموسعة
   - لا تظهر `Users/Groups`
   - `.../admin/auth/user/` و `.../admin/auth/group/` → `403`
